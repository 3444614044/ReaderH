自研引擎

识别更智能，排版更友好

两道引擎各司其职：一个负责从杂乱的网页里把正文捞出来，一个负责把它排成书。

  • ◆识别引擎：页面加载完成即在 WebView 内执行抽取脚本，按标签权重、文本密度、链接占比综合打分选出正文块，再清洗广告、导航、推荐位与空节点，同步还原懒加载图片的真实地址。
  • ◆排版引擎：把 HTML 转成带样式的文本流交给 StaticLayout 逐行量高切页，无论字号调到多大、行距调多松，都不会出现半行文字被截断。
  • ◆增量重排：改字号、转横屏、续下一章时只重算受影响的部分，已渲染页面的缓存不丢，翻页不跳、不闪。

核心能力

手机上的阅读，本该如此

从 Circle 阅读助手扩展移植而来，再针对小屏与长文做了专门改造。

📖

仿真翻页

手指从右下角掀起页面，折痕处带阴影，背面透出下一页内容——和真实纸张一致。另支持覆盖、滑动、无动画三种方式。

📐

按屏分页

不是无限下滑，而是按屏幕尺寸精确切成一页页。字号、行距、段距、分栏怎么改，都不会出现半行截断。

🎨

所见即所得

底部面板拖动滑杆，正文实时跟着变。字号、行距、段距、背景、亮度，改完立刻能看到效果。

🔗

自动续章

读到最后一页之前，后台已悄悄抓取「下一章」正文并追加分页，翻过去就是下一章，无缝衔接。

🗂️

书架与进度

喜欢的文章一键存入书架，记录读到第几页。下次点开自动回到上次的位置，长篇也能放心放下。

🌐

内置浏览器

自带地址栏、前进后退、进度条与桌面版 UA 切换。识别到正文就浮出阅读按钮，不用再来回复制链接。

问答

你可能会问

ReaderH 和 Circle 阅读助手是什么关系？

ReaderH 是 Circle 阅读助手（Chrome / Edge / Firefox 扩展）能力在 Android 端的复刻实现：把「抓正文 + 重排版」搬进一个内置浏览器的独立 App，并针对手机屏幕补上了按屏分页、仿真翻页与自动续章。

为什么用仿真翻页而不是滚动？

手机上滚动阅读容易被通知、误触打断，也难以感知进度。按屏分页 + 仿真翻页让你始终知道「读到第几页、还剩多少」，长篇内容尤其明显。

所有网页都能识别吗？

绝大多数新闻、博客、文档站点没问题。对重度依赖前端渲染或反爬的站点，可在设置里开启 JavaScript 或桌面版 UA 改善。识别不到正文时不会强行跳转阅读模式。

小说站点能自动接下一章吗？

可以。抽取引擎会同时解析页面里的「下一页 / 下一章」链接，读到倒数第二页即后台预取并追加分页。个别站点规则特殊时需补充解析规则。

依赖好装吗？

仓库地址已全部指向腾讯软件源镜像（插件、Google Maven、Maven 公共代理、Gradle 发行包四组），国内网络下同步更稳。若你能直连官方仓库，把 settings.gradle.kts 里的三组地址换回 google() / mavenCentral() 即可。
